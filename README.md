> 상세 규칙은 `spec-kit/` 폴더의 문서가 정본이다. 이 README와 충돌하면 `spec-kit/` 문서를 따른다.

## 1. 프로젝트 개요
- 목표: 타겟 사이트 **https://blancdoux.com/** (더랩 바이 블랑두)와 **디자인은 동일**하게, **내부 레이아웃은 다르게** 구현한다.
- 기술: **HTML / CSS / JavaScript** (프레임워크, 빌드 도구 없이 순수 코드)
- 작업 방식: 바이브코딩. 사람이 방향을 주고 에이전트가 구현한다.

## 2. 가장 먼저 읽을 파일 (순서 고정)
1. `spec-kit/agent.md` — 디자이너/개발자 일반 규칙 + 이 사이트 전용 규칙 (박스, 글자, 색상, 레이아웃)
2. (있다면) `spec-kit/` 안의 나머지 문서 — 파일명 순서대로 읽는다.

규칙 문서를 읽기 전에는 **코드를 한 줄도 쓰지 않는다.**

## 3. 절대 규칙 요약 (상세는 `spec-kit/agent.md`)

### 레이아웃
- 박스 구조는 **겉박스 > 속박스 > 파티션 박스** 3단만 쓴다.
- 겉박스 전체 구조: `header` + (`main` > `section`) + `footer`
- 속박스: 이름은 **`.inner-box`**로 통일. `max-width` + 중앙정렬. 사이트에 max-width가 없으면 `1920px`.
- 파티션 박스: 기본 **flex**, 줄바꿈이 필요하면 `flex-wrap`. **파티션 박스에 Grid 금지.** (파티션 안의 내용박스에만 필요 시 grid)

### 디자인 (사이트와 동일하게)
- 박스 크기, 패딩, 마진, 글자, 색상은 `spec-kit/agent.md`의 수치만 사용한다.
- 색상은 문서의 팔레트 밖 값을 임의로 추가하지 않는다.
- 문서에 `[미확인]`으로 표시된 값은 **추측해서 채우지 않는다.** CSS 변수로 비워 두고 사람에게 확인을 요청한다.

## 4. 작업 순서
1. `spec-kit/agent.md`를 읽는다.
2. 작업할 섹션/페이지를 정하고, **구현 계획을 먼저 짧게 보고**한다. (어떤 section을 만들지, 어떤 파티션으로 나눌지)
3. 공통 파일부터 만든다: CSS 변수(색상/폰트/간격) → 리셋/공통 CSS → `.inner-box`, 파티션 공통 클래스
4. `header` → `main`의 `section`들(위에서 아래 순서) → `footer` 순으로 구현한다.
5. 섹션 하나가 끝날 때마다 규칙 위반이 없는지 스스로 점검하고 보고한다.

## 5. 점검 체크리스트 (섹션 완료 시마다)
- [ ] 겉박스 > 속박스(`.inner-box`) > 파티션 3단을 지켰다
- [ ] 파티션 박스에 grid를 쓰지 않았다
- [ ] 색상/글자/간격 값이 문서 수치와 일치한다
- [ ] 문서에 없는 값은 임의로 만들지 않고 변수로 비워 두었다
- [ ] 클래스명은 의미 기반이고, 원본 사이트의 `xx-wrap / xx-container / xx-content` 3중 래퍼를 쓰지 않았다

## 6. 하지 말 것
- 원본 사이트의 레이아웃(래퍼 중첩, 구조)을 그대로 복사하지 않는다. 시각 디자인만 같게 한다.
- 원본 사이트의 코드, 이미지, 문구를 그대로 가져다 쓰지 않는다. 이미지는 자리표시용으로 대체하고 사람이 교체한다.
- 요청받지 않은 라이브러리/프레임워크를 추가하지 않는다.
- 규칙이 모호하면 임의로 판단하지 말고 **한 번에 하나씩** 사람에게 질문한다.

## 7. 현재 미확정 항목 (사람이 확인 후 `spec-kit/agent.md`에 채움)
- 폰트 패밀리, 제목/메뉴/푸터 글자 크기, 헤더 높이, 섹션 간 간격, 반응형 기준점
- 아이콘 배너 영역의 실제 max-width (1400 vs 1600)
- 위 항목은 채워지기 전까지 CSS 변수로 비워 둔다.
