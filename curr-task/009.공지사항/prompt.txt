[ 공지사항 게시판 생성 프롬프트 ]
-첨부: 게시판 각 화면(4가지)
-프롬프트(원본):
첨부된 화면과 동일하게 공지사항 게시판을 만들거야. DB없이 로컬스토리지로 개발할거야. 개발 후 파이어베이스 DB로 마이그레이션 할 예정이야. 따라서 localstorage_to_firebase_guidelines.md 파일 지침에 따라 개발 구현해야해.

-프롬프트(수정:클로드)
첨부한 화면 2장(공지사항, 자주 묻는 질문)과 동일한 디자인·레이아웃으로 게시판 2개를 만들어줘.

[개발 방식]
- DB 없이 localStorage로 구현한다.
- 이후 Firebase DB로 마이그레이션할 예정이므로, 반드시 localstorage_to_firebase_guidelines.md 지침을 먼저 읽고 그대로 따른다.
- 지침과 이 프롬프트가 충돌하면 지침을 우선하고, 충돌 내용을 알려준다.

[공통 화면 구성]
- 상단 안내바 / 헤더 / 브레드크럼(홈 / 게시판 / 페이지명) / 페이지 타이틀 / 목록 테이블 / 검색 영역 / 페이지네이션
- 검색 영역: 기간 선택(일주일 등) + 검색 대상(제목) + 입력창 + '찾기' 버튼
- 페이지네이션: 이전/다음 + 현재 페이지 번호

[공지사항]
- 서브타이틀: "더랩 바이 블랑두의 소식을 확인해 보세요."
- 컬럼: 번호 / 제목 / 작성자 / 작성일
- 번호는 최신글이 큰 번호(내림차순)

[자주 묻는 질문]
- 상단 카테고리 탭: 전체 / 상품 / 주문 / 결제 (선택 탭 강조, 클릭 시 필터링)
- 컬럼: 번호 / 제목 / 카테고리 / 작성자
- 제목은 "Q. [카테고리] 질문" 형식

[기능]
- 목록 조회, 검색(기간+제목), 카테고리 필터(FAQ), 페이지네이션
- 글 클릭 시 상세 보기 (FAQ는 클릭 시 답변 펼침도 가능)
- 초기 더미 데이터는 스크린샷의 글로 시드하고, 데이터가 이미 있으면 덮어쓰지 않는다.

[데이터 규칙]
- localStorage 접근은 별도 데이터 접근 모듈로 분리하고, UI 코드에서 localStorage를 직접 호출하지 않는다.
- 데이터 접근 함수는 지침의 Firebase 전환 구조에 맞게 비동기(async) 형태로 작성한다.
- 컬렉션/필드명은 지침을 따른다.

[작업 순서]
1. 지침 파일을 읽고 핵심 규칙을 5줄 이내로 요약해서 먼저 보여준다.
2. 파일 구조를 제안하고 승인을 받은 뒤 구현한다.
