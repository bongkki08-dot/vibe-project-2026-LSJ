## 메인 비주얼(Hero Section) 반응형 구현 명세

### 1. 기본 구조
- 전체 화면을 하나의 Hero Section으로 구성한다.
- 배경 이미지가 들어가는 비주얼 영역을 중심으로 구현한다.
- 기존 헤더 및 내비게이션 구조는 유지한다.
- 슬라이드 형태로 구성하며, 이미지와 텍스트 콘텐츠는 슬라이드별로 변경될 수 있도록 설계한다.
- 실제로 사용된 이미지는 images/used 폴더에 있는 이미지를 사용한다.

### 2. 데스크탑 레이아웃 (기본 구조)
- 배경 이미지를 Hero 영역 전체에 배치한다.
- 이미지 위에 텍스트 콘텐츠를 오버레이한다.
- 텍스트는 왼쪽 하단에 정렬한다.
- 상품 이미지는 배경 이미지의 오른쪽 영역에 위치하도록 한다.
- 텍스트와 상품 이미지가 겹치지 않도록 배치한다.
- 배경 이미지는 영역에 맞춰 자연스럽게 크롭하되, 주요 상품이 잘리지 않도록 `background-position` 또는 `object-position`을 조정한다.
- 텍스트 영역은 제목과 More View 버튼으로 구성한다.

### 3. 모바일 레이아웃 (640px 이하)
- 데스크탑의 오버레이 레이아웃을 해제하고 모바일 전용 레이아웃으로 재구성한다.
- 상단은 배경 이미지 중심의 비주얼 영역으로 구성한다.
- 상품 이미지가 화면 중앙에 충분히 크게 노출되도록 이미지 크기와 위치를 조정한다.
- 텍스트 콘텐츠는 이미지 아래 별도의 영역에 배치한다.
- 텍스트는 왼쪽 정렬하며 제목과 More View 버튼을 세로로 배치한다.
- 모바일에서는 이미지 영역과 텍스트 영역이 명확하게 구분되어야 한다.
- 데스크탑과 모바일의 이미지 크롭 및 위치가 다르므로 필요하면 별도의 반응형 이미지 또는 배경 위치값을 적용한다.

### 4. 고정 UI 요소 (Fixed Position)
다음 요소는 Hero Section 내부가 아닌 브라우저 뷰포트를 기준으로 고정한다.

- **슬라이드 인디케이터:** 화면 하단 중앙에 고정한다. 현재 슬라이드 상태를 시각적으로 구분하며, 화면 크기가 변경되어도 항상 동일한 위치를 유지한다.
- **SNS 버튼:** 화면 오른쪽 하단에 고정한다. 콘텐츠 영역이나 슬라이드 높이에 영향을 받지 않아야 한다.
- 고정 UI 요소는 다른 콘텐츠보다 높은 `z-index`를 적용한다.
- 모바일에서도 고정 위치를 유지하되, 화면 가장자리와 겹치지 않도록 적절한 여백 및 `safe-area-inset`을 고려한다.

### 5. 반응형 구현 방식
- Desktop First 방식으로 구현한다.
- 데스크탑 레이아웃을 기본 CSS로 먼저 작성한다.
- `@media (max-width: 640px)`에서 모바일 레이아웃으로 전환한다.
- 640px 초과에서는 데스크탑 레이아웃을 유지한다.
- 모바일 전환 시 단순히 요소의 크기만 축소하지 말고, 이미지와 텍스트의 배치 구조 자체를 변경한다.
- 불필요한 중복 마크업을 최소화하고 CSS 레이아웃 및 위치 속성을 활용한다.

### 6. 구현 시 주의사항
- 인디케이터와 SNS 버튼은 Hero Section의 높이나 위치에 영향을 받지 않도록 독립적으로 관리한다.
- 슬라이드 전환 시 이미지, 텍스트, 인디케이터의 상태가 함께 변경되어야 한다.
- 데스크탑과 모바일 모두 상품 이미지의 비율이 왜곡되지 않도록 한다.
- 모바일에서 텍스트 영역이 이미지 위로 겹쳐 올라오지 않도록 한다.
- 가로 스크롤이 발생하지 않도록 반응형 너비를 관리한다.
