# Spec-Kit: Designer Specification
**기준 환경:** Vanilla HTML / CSS / JavaScript  
**문서 목적:** 사이트 전반의 시각적 일관성, 반응형 규칙, 컴포넌트 상태 및 접근성 기준을 정의한다.

> 이 문서는 디자인 시스템의 기본 규칙이다. 사이트의 실제 브랜드 가이드, 화면 설계서, 사용자 요구사항이 별도로 제공되면 해당 자료를 우선한다. 아래 색상·타이포그래피 값은 초기 제안값이며, 프로젝트 확정값으로 간주하지 않는다.

## 1. 역할과 작업 원칙

1. 사용자 요구사항, 사이트 목적, 주요 사용자, 콘텐츠 구조를 먼저 파악한다.
2. 화면을 설계하기 전에 페이지 구조와 사용자 흐름을 정리한다.
3. 디자인 결정은 이 문서의 토큰과 컴포넌트 규칙을 우선 사용한다.
4. 요구사항에 없는 기능이나 콘텐츠를 임의로 추가하지 않는다. 필요해 보이는 개선안은 제안으로 분리한다.
5. 구현 가능성을 고려해 실제 HTML/CSS로 재현할 수 있는 디자인을 정의한다.
6. 개발자에게 전달할 때는 시각적 설명뿐 아니라 크기, 간격, 상태, 반응형 변화, 동작을 명시한다.

## 2. Design System & Tokens

### 2.1 Color Palette

아래 값은 초기 예시다. 프로젝트의 브랜드 방향과 실제 화면에 맞춰 확정하고, 확정 후에는 `variables.css`와 동일하게 유지한다.

```css
:root {
  /* Brand */
  --color-primary: #111111;
  --color-brand-blue: #2B6CB0;
  --color-brand-accent: #1A365D;

  /* Surface */
  --color-bg-primary: #FFFFFF;
  --color-bg-secondary: #F7FAFC;
  --color-surface: #FFFFFF;
  --color-border: #E2E8F0;

  /* Text */
  --color-text-main: #1A202C;
  --color-text-sub: #718096;
  --color-text-muted: #A0AEC0;
  --color-text-inverse: #FFFFFF;

  /* Status */
  --color-success: #2F855A;
  --color-warning: #B7791F;
  --color-error: #C53030;
  --color-sale-badge: #E53E3E;
  --color-star-rating: #ECC94B;

  /* Focus */
  --color-focus: #2563EB;
}
```

- 색상은 용도별 토큰으로 사용하고 컴포넌트마다 임의의 색상값을 반복 선언하지 않는다.
- 본문 텍스트와 배경의 대비를 충분히 확보한다. 색상만으로 상태나 오류를 전달하지 않는다.
- 실제 프로젝트에서 사용하지 않는 토큰은 제거하거나 보류 상태로 둔다.

### 2.2 Typography

```css
:root {
  --font-family-base: "Pretendard", -apple-system, BlinkMacSystemFont,
    "Segoe UI", Roboto, sans-serif;

  --font-size-caption: 0.75rem; /* 12px */
  --font-size-body-sm: 0.875rem; /* 14px */
  --font-size-body: 0.9375rem; /* 15px */
  --font-size-h2: 1.25rem; /* 20px */
  --font-size-h1: 1.75rem; /* 28px */
  --font-size-display: 2.25rem; /* 36px */

  --line-height-tight: 1.2;
  --line-height-heading: 1.3;
  --line-height-body: 1.5;
}
```

| 역할 | 크기 | 행간 | 굵기 |
|---|---:|---:|---:|
| Display / Hero | 36px | 1.2 | 700 |
| Heading 1 | 28px | 1.3 | 600–700 |
| Heading 2 | 20px | 1.4 | 600 |
| Body | 15px | 1.5 | 400–500 |
| Body Small | 14px | 1.5 | 400 |
| Caption | 12px | 1.2 | 400–600 |

- 작은 화면에서는 제목 크기를 유동적으로 조정할 수 있다.
- 긴 문장과 한글 콘텐츠가 실제 화면에서 잘리지 않는지 확인한다.
- Pretendard를 별도로 제공하지 않는 경우를 고려해 폴백 폰트를 지정한다.

### 2.3 Spacing, Radius, Shadow

```css
:root {
  --spacing-xs: 4px;
  --spacing-sm: 8px;
  --spacing-md: 16px;
  --spacing-lg: 24px;
  --spacing-xl: 40px;
  --spacing-2xl: 64px;

  --radius-sm: 4px;
  --radius-md: 8px;
  --radius-lg: 12px;

  --shadow-card: 0 4px 12px rgba(0, 0, 0, 0.08);

  --container-max: 1280px;
  --page-gutter: 24px;
}
```

- 간격은 토큰을 우선 사용한다.
- 카드, 버튼, 입력창의 모서리와 그림자는 공통 규칙을 따른다.
- 작은 화면에서는 좌우 여백과 섹션 간격을 줄이되 콘텐츠가 답답해지지 않게 한다.

## 3. Layout & Responsive Rules

### 3.1 Breakpoints

| 구분 | 기준 |
|---|---|
| Mobile | 0–767px |
| Tablet | 768–1023px |
| Desktop | 1024px 이상 |

- 브레이크포인트는 기본 기준이다. 실제 레이아웃이 깨지는 지점이 다르면 콘텐츠에 맞춰 조정하고 변경 사실을 명시한다.
- `1024px` 경계에서 중복되거나 비는 구간이 없어야 한다.
- 데스크톱 콘텐츠는 기본 최대 너비 `1280px`을 사용하고 화면 중앙에 배치한다.
- 모바일은 가로 스크롤이 발생하지 않도록 한다. 표나 특수 콘텐츠처럼 필요한 경우 별도 처리 규칙을 정의한다.

### 3.2 Responsive Behavior

각 페이지/컴포넌트에 대해 다음을 명시한다.

- 열 수와 정렬 방식 변경
- 콘텐츠 순서 변경 여부
- 이미지 비율 및 크롭 방식
- 제목·본문의 크기와 줄바꿈
- 내비게이션 전환 방식(전체 메뉴, 햄버거, 드로어 등)
- 버튼의 너비와 터치 영역
- 숨김 처리되는 요소와 대체 콘텐츠

단순히 요소를 축소하는 방식으로 반응형을 처리하지 않는다. 작은 화면에서 정보 우선순위와 사용 흐름을 유지한다.

## 4. Component Specifications

모든 주요 컴포넌트는 기본형뿐 아니라 상태와 동작을 정의한다.

### 4.1 공통 명세 항목

- 목적 및 사용 위치
- 구성 요소와 콘텐츠 계층
- 크기, 간격, 정렬, 색상, 타이포그래피
- 기본 / Hover / Focus / Active / Disabled / Error 상태(해당하는 경우)
- 모바일·태블릿·데스크톱 변화
- 클릭·키보드·터치 동작
- 빈 상태, 로딩 상태, 오류 상태(해당하는 경우)

### 4.2 Product Card (상품형 사이트에서 사용하는 경우)

- 이미지 비율: 기본 `1:1.25` 제안값. 실제 이미지와 콘텐츠에 따라 조정한다.
- 이미지: 비율 유지 및 `object-fit` 기준 명시
- 배지: 위치, 우선순위, 여러 배지의 표시 규칙 정의
- 상품명: 최대 줄 수와 말줄임 처리 정의
- 가격·할인율: 정보 위계와 표시 순서 정의
- Hover 효과는 포인터 환경에서만 제공하고, 터치 환경에서는 Hover에 의존하지 않는다.

### 4.3 Header / Navigation / Drawer

- 헤더 높이 초기값: Desktop 80px, Mobile 60px(프로젝트에 맞게 확정).
- 고정 헤더 여부와 스크롤 시 동작을 정의한다.
- 드로어의 열림 방향, 너비, 오버레이, 닫기 동작을 정의한다.
- 메뉴 열림 상태에서 배경 스크롤 처리, 바깥 영역 클릭, ESC 닫기 동작을 정의한다.
- 현재 페이지 또는 선택된 메뉴 상태를 시각적으로 구분한다.

### 4.4 Interactive Components

탭, 아코디언, 모달, 캐러셀, 드롭다운, 폼 등은 다음을 정의한다.

- 트리거와 사용자 동작
- 초기 상태 및 상태 전환
- 여러 항목이 동시에 열릴 수 있는지
- 키보드 조작 방식
- 닫기 및 취소 방식
- 데이터가 없거나 오류가 발생한 경우의 표시

## 5. Interaction & Accessibility

1. 링크는 이동, 버튼은 실행 등 의미에 맞는 UI 요소를 사용하도록 설계한다.
2. 키보드 포커스가 눈에 보이도록 한다.
3. 텍스트와 배경의 명도 대비를 고려하고, 상태를 색상만으로 표현하지 않는다.
4. 이미지에는 콘텐츠 의미에 맞는 대체 텍스트가 필요하다. 장식 이미지는 빈 대체 텍스트를 사용한다.
5. 입력 필드에는 명확한 라벨과 오류 안내가 있어야 한다.
6. 모달·드로어는 열림/닫힘 상태와 포커스 이동을 고려한다.
7. 터치 환경에서 조작 요소가 충분한 크기와 간격을 갖도록 한다.

## 6. Image & Asset Guidelines

- 이미지 파일명, 포맷, 비율, 사용 위치를 일관되게 관리한다.
- 제공된 에셋을 우선 사용하며, 임의로 유사 이미지를 대체하지 않는다.
- 이미지의 크롭 위치가 중요하면 `object-position` 또는 별도 아트 디렉션을 명시한다.
- 아이콘은 프로젝트 내 동일한 스타일 체계를 사용한다.
- 대체 이미지가 필요한 경우 임의 제작하지 말고 플레이스홀더 사용 여부를 명시한다.

## 7. Design Handoff & Review

개발자에게 전달하는 산출물에는 다음이 포함되어야 한다.

- 페이지별 섹션 순서와 레이아웃
- 디자인 토큰 및 컴포넌트 명세
- 반응형 변화 기준
- 주요 인터랙션과 상태
- 이미지·아이콘 등 에셋 매핑
- 확정되지 않은 항목과 개발 전 확인이 필요한 질문

검수 시에는 원본 요구사항과 화면 설계의 일치, 반응형 레이아웃, 콘텐츠 누락, 인터랙션 상태, 접근성을 확인한다. 의도적인 차이가 있으면 이유를 기록한다.
