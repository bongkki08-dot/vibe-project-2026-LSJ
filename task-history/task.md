# 작업 이력 및 이어서 작업하기

## 다음 작업 시작 절차
1. 이 파일을 먼저 읽어 완료된 범위, 현재 구현 상태, 미확정 사항을 확인한다.
2. 사용자의 현재 요청과 해당 작업의 `curr-task/` 프롬프트를 확인한다.
3. 저장소 파일과 상태를 확인한 뒤, 완료된 작업을 반복하지 말고 미완료 범위부터 이어서 진행한다.
4. 새 작업이 끝나면 이 파일의 현재 상태와 미확정 항목을 갱신한다.

이 파일은 작업 인계용 요약이며, 현재 사용자의 요청과 프로젝트 명세가 우선한다.

## 직전 작업: 데스크톱 홈 상단 화면 구현

### 요청
- README와 사이트 규칙을 확인하고, 첨부된 데스크톱 화면을 참고해 홈 상단을 구현한다.
- 데스크톱을 우선 지원하고, README에서 지정한 CSS 기본 파일 구성을 만든다.
- 이미지는 만들거나 가져오지 않고, 이미지가 들어갈 자리를 박스로 표시한다.

### 확인한 규칙과 제약
- 프로젝트는 프레임워크 없이 HTML/CSS/JavaScript로 구성한다.
- 페이지의 기본 구조는 `header`, `main > section`, `footer`다.
- 콘텐츠는 `.inner-box`를 사용하고, 파티션은 flex로 구성한다. 파티션 자체에 grid를 사용하지 않는다.
- 사이트 규칙의 확인된 값: 콘텐츠 최대폭 `1600px`, 좌우 패딩 `48px`, 히어로 기준 높이 `913px`.
- 미확정인 폰트, 제목/메뉴 글자 크기, 헤더 높이 등은 임의 확정하지 않고 CSS 변수로 남긴다.
- README가 지정한 `spec-kit/agent.md`는 현재 없었다. 대신 `spec-kit/AGENTS-blancdoux.md`, `spec-kit/개발자_Spec-kit_수정본.md`, `spec-kit/디자이너_Spec-kit_수정본.md`를 확인했다.
- 화면 문구는 원본 문구를 복제하지 않고 대체 문구를 사용했다.

### 구현 완료
- `index.html`: 한국어 문서 기본 구조, 상단 프로모션 띠, 메뉴/로고/검색·계정·장바구니 헤더, 히어로 카피, 상품 이미지 자리 박스, 화살표/페이지네이션 장식, 빈 푸터를 구성했다.
- `css/reset.css`, `css/variables.css`, `css/base.css`, `css/layout.css`, `css/style.css`: CSS 기본 구조와 순서별 import를 만들었다.
- `css/components/header.css`, `css/components/hero.css`: 헤더와 히어로 스타일을 분리했다.
- `js/main.js`: 프로모션 닫기 버튼을 구현했다.
- 히어로 높이는 `min(913px, 48vw)`로 두어 기준 데스크톱 크기에서는 913px을 유지하고, 더 좁은 화면에서는 화면 폭에 맞춰 줄어들게 했다.
- CSS 토큰에는 현재 확인되지 않은 값을 빈 사용자 지정 속성으로 남겼다: `--ff-base`, `--fs-title`, `--fs-menu`, `--fs-promotion`, `--header-height`, `--hero-copy-inset`.

### 검증 결과
- 브라우저에서 로컬 페이지를 열어 1420×765 및 1905×948 크기를 확인했다.
- 1905px 너비에서 히어로 높이 913px, 가로 넘침 없음, 안내 띠 닫기 동작을 확인했다.
- `git diff --check` 통과.
- Node.js가 설치되지 않아 `node --check`는 실행할 수 없었다. 브라우저에서 페이지와 닫기 동작은 확인했다.
- 검증용 로컬 HTTP 서버는 종료했다.

### 후속 작업 후보 / 미확정 사항
- 사용자가 확인할 때까지 비워 둔 폰트, 글자 크기, 헤더 높이, 히어로 카피 위치 값을 임의로 채우지 않는다.
- 현재 메뉴/검색/로그인/장바구니는 시각적 버튼만 있으며 동작은 구현하지 않았다.
- 히어로 화살표와 페이지네이션도 정적인 화면 요소이며 슬라이더 동작은 구현하지 않았다.
- `자세히 보기`는 대상 섹션이 아직 없어 동작 링크가 아닌 표시 요소다.
- 실제 상품 이미지 또는 배경 에셋은 사용자가 제공하거나 요청하기 전까지 추가하지 않는다.
- 이후 작업에서는 먼저 현재 파일과 Git 상태를 확인해, 이 기록과 실제 코드가 달라진 경우 실제 저장소 상태를 우선한다.

## 이번 작업: Hero 반응형 슬라이드 구현

### 요청
- README와 이 작업 이력을 읽고 기존 헤더는 유지한 채 Hero를 데스크톱/모바일 반응형으로 구성한다.
- `images/used`의 데스크톱 및 모바일 배너 이미지 사용.
- 데스크톱에서는 이미지 위 왼쪽 아래 카피, 모바일(640px 이하)에서는 정사각형 비주얼 아래 별도 카피.
- 슬라이드 이동과 인디케이터 상태를 동기화하고, 인디케이터와 SNS 버튼은 뷰포트에 고정한다.

### 구현 완료
- `index.html`: Hero를 4개 슬라이드로 구성하고 데스크톱/모바일 이미지 소스를 `<picture>`로 연결했다.
  - 블루 클레이 마스크: `dt_72cf80038201f60d115f6ae10b2d7eea.jpg` / `mob_8f4b1698d6957b294e518cbe62bddd93.webp`
  - 젤리 미스트: `dt_12f453b931b1c26f9b3196afde8ffa0d.webp` / `mob_eb7aacd5aafc68c8075130e10291654d.webp`
  - 그린 패드: `dt_1b8cce9556991156d23db92d751db0e7.jpg` / `mob_35aec6f082662398a45eb01acd65edc5.png`
  - 보습 로션: `dt_852f27e81e5b0321db609605a711ed8e.jpg` / `mob_cafe882f945584af91534bb253529e72.jpg`
- `css/components/hero.css`: 데스크톱 오버레이와 640px 이하의 이미지 위/카피 아래 레이아웃을 구현했다. 슬라이드 인디케이터 및 카카오 상담 버튼은 Hero와 형제인 고정 도구 섹션에 배치하고 뷰포트 기준 fixed로 처리했다.
- `css/variables.css`: 제공된 데스크톱/모바일 샘플을 기준으로 `--fs-title: 28px`, `--fs-title-mobile: 16px`로 지정했다. 폰트 패밀리 등 나머지 미확정 값은 비워 두었다.
- `js/main.js`: 이전/다음 버튼과 인디케이터로 4개 슬라이드를 순환하며 보임 상태와 활성 인디케이터/`aria-current`를 동기화했다. 자동 재생은 요청되지 않아 추가하지 않았다.
- 기존 헤더 마크업과 상단 안내 닫기 동작은 유지했다.

### 검증 결과
- 브라우저에서 모바일 390×844, 데스크톱 1440×900 및 1905×948 크기를 확인했다.
- 640px에서 모바일 레이아웃, 641px에서 데스크톱 레이아웃으로 전환됨을 확인했다.
- 4개 모바일 이미지의 로딩, 다음/이전 및 각 인디케이터의 슬라이드 상태 동기화, 고정 요소 위치, 가로 넘침 없음을 확인했다.
- 데스크톱에서 Hero 높이 913px, 인디케이터/SNS 버튼의 `position: fixed`를 확인했다.
- `git diff --check` 통과. 프로젝트에 별도 테스트 러너가 없고 Node.js도 사용할 수 없어 자동 테스트 대신 브라우저 검증을 수행했다.

### 남은 사항
- 각 슬라이드의 `More View`와 카카오 상담 버튼은 대상 URL/동작 정보가 없어 시각 UI로만 구성했다.
- 자동 재생은 명세에서 필수로 지정하지 않아 구현하지 않았다.
- 헤더 높이·폰트 패밀리 등 나머지 미확정 값은 계속 CSS 변수의 미확정 상태로 유지한다.

## 다음 작업: Off-canvas 사이드 메뉴

### 요청
- 헤더 햄버거 버튼에서 왼쪽 사이드 패널을 연다.
- 데스크톱은 420px, 모바일(640px 이하)은 너비 90vw로 표시하고 오른쪽 페이지와 딤을 남긴다.
- 상단 로그인/회원가입 영역은 고정하고 메뉴 목록만 내부 스크롤한다.
- BRAND, ALL, 라인별 제품 아코디언과 베스트/이벤트/COMMUNITY를 제공한다.
- X, 딤, Escape로 닫고 열린 동안 배경 스크롤과 포커스를 제어한다.

### 구현 완료
- `index.html`: 햄버거 버튼에 `aria-expanded`/`aria-controls`를 연결하고, 딤 배경과 대화상자 역할의 사이드 메뉴를 추가했다. 로그인 안내와 버튼, 지정 카테고리/하위 메뉴, 커뮤니티 메뉴를 구성했다.
- `css/components/side-menu.css`: 데스크톱 420px 및 640px 이하 90vw 패널, 350ms 슬라이드/딤 전환, `100dvh`, 고정 로그인 영역과 독립 스크롤 콘텐츠, 접힘 상태 화살표를 구현했다. reduced-motion 설정도 반영했다.
- `css/style.css`: 사이드 메뉴 컴포넌트 스타일을 연결했다.
- `js/main.js`: 햄버거 열기, X/딤/Escape 닫기, 닫힌 뒤 inert/hidden 처리, 배경 스크롤 잠금, 포커스 이동/복귀 및 Tab 순환, 아코디언 토글을 구현했다.
- 기존 헤더, 프로모션 닫기, Hero 슬라이드 기능은 보존했다.

### 검증 결과
- 브라우저에서 데스크톱 1440×900/1440×480, 모바일 390×844를 확인했다.
- 데스크톱 패널 너비 420px, 모바일 패널 351px(390px의 90%), 전체 뷰포트 높이를 확인했다.
- 딤 애니메이션 최종 opacity 0.55, 패널 진입 위치, 배경 `overflow: hidden`을 확인했다.
- 메뉴 콘텐츠 자체의 스크롤과 고정 상단 영역 유지, BRAND 아코디언 접힘, Escape/X/딤 닫기, 포커스 복귀와 닫힌 후 hidden/inert 상태를 확인했다.
- 화면 ID 중복 검사와 `git diff --check` 통과.

### 남은 사항
- 로그인/회원가입 버튼과 메뉴 링크는 실제 페이지 경로/동작이 제공되지 않아 UI 및 임시 앵커만 구성했다. 실제 라우트가 정해지면 링크를 연결한다.

## 이번 보완: 사이드 메뉴 버튼 hover 및 아코디언 애니메이션

### 요청
- 로그인 버튼 hover 색을 회원가입 버튼 기본 상태(짙은 회색 배경/흰 글자)와 같게 한다.
- 회원가입 버튼 hover 시 검은색으로 바꾼다.
- 하위 메뉴 아코디언이 열리고 닫힐 때 부드럽게 움직이도록 한다.

### 구현 완료
- `css/components/side-menu.css`: 로그인/회원가입 버튼에 200ms 색상 전환을 적용했다. 로그인 hover는 `--c-text` 배경과 흰 글자, 회원가입 hover는 `--c-black` 배경을 사용한다.
- `css/components/side-menu.css`: 하위 메뉴의 높이·투명도·위치·하단 패딩을 transition 처리했다.
- `js/main.js`: 하위 메뉴의 현재 높이를 측정한 뒤 실제 픽셀 높이를 애니메이션하고, 닫힘 전환이 끝난 뒤 `hidden`으로 처리한다. 빠른 재조작 시 타이머를 취소하며, 애니메이션이 끝나면 높이 스타일을 초기화한다.

### 검증 결과
- 브라우저에서 로그인 hover `rgb(64, 64, 64)` 배경/흰 글자, 회원가입 hover 검정 배경/흰 글자를 확인했다.
- 아코디언 접기에서 높이가 132px → 약 26px → 0px으로, 펼치기에서 0px → 약 95px → 132px으로 변한 뒤 완료되는 것을 확인했다. 접힌 뒤에만 `hidden` 상태가 적용된다.
- `git diff --check` 통과.
